Identity and Access Management

Laboratório 279 — Introdução ao AWS IAM

Um estudo prático sobre como controlar quem pode acessar recursos da AWS e quais ações cada identidade pode executar.

IAM Amazon EC2 Amazon S3 Segurança
01

Objetivo do laboratório

Configurar uma política de senhas, analisar usuários e grupos do IAM, atribuir permissões e testar como essas permissões determinam o acesso aos serviços da AWS.

02

Como o IAM organiza o acesso

Usuários

Identidades que podem receber permissões para acessar recursos da AWS.

Grupos

Conjuntos de usuários que compartilham permissões por meio de políticas.

Políticas

Documentos que definem as ações permitidas ou negadas.

Permissões

Determinam quais operações uma identidade pode realizar em cada recurso.

03

Distribuição das permissões

No laboratório, cada usuário foi associado a um grupo com permissões diferentes.

Usuário Grupo Acesso concedido
user-1 S3-Support Leitura no Amazon S3
user-2 EC2-Support Leitura no Amazon EC2
user-3 EC2-Admin Visualizar, iniciar e parar instâncias EC2
04

Teste de acesso: permissão negada

O usuário user-2 tentou parar uma instância EC2, mas a AWS bloqueou a operação porque nenhuma política de permissões vinculada à identidade autorizava a ação ec2:StopInstances.

!

Acesso negado

O usuário podia consultar informações das instâncias, mas não tinha autorização para interrompê-las.

05

Evidências do laboratório

06

O que aprendi

  • Os grupos ajudam a organizar permissões para vários usuários.
  • As políticas determinam quais ações podem ser executadas.
  • Permitir a leitura de um recurso não significa permitir sua alteração.
  • O princípio do menor privilégio reduz permissões desnecessárias.
  • Testar diferentes identidades ajuda a confirmar se o acesso está configurado corretamente.
